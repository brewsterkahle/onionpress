# DMG window assets

Two files that style the installer window you see after opening
`onionpress.dmg`. `build/build-dmg-simple.sh` copies both into the mounted
image; when they are present they always win over the AppleScript fallback,
which therefore never runs in practice.

## `dmg-background.png` — generated

`build/create-dmg-background.py` produces it from
`assets/branding/logo.png` and `assets/branding/story.png`:

```bash
python3 build/create-dmg-background.py build/dmg-assets/dmg-background.png \
    --logo assets/branding/logo.png \
    --story assets/branding/story.png
```

Needs Pillow. The output is **equivalent, not byte-identical** — it depends
on the installed Pillow's LANCZOS resampling, its zlib, and on how
`/System/Library/Fonts/Helvetica.ttc` rasterises on that macOS version.

Do not change its **dimensions**. The 640x620-point window geometry is
hardcoded in `DS_Store`'s `bwsp` record and in the AppleScript fallback, and
neither adapts.

## `DS_Store` — a capture, not a build

This one cannot be regenerated by a script. It is a Finder `.DS_Store`
captured from a correctly-styled DMG, and it encodes machine-specific state:

- an `icvp` record holding a classic Alias blob pointing at
  `/Volumes/OnionPress/.background/dmg-background.png`
- volume creation dates and file IDs
- the literal build-machine path of the read-write image it was captured from

That last one is a real leak: the committed file contains
`/Users/brewster/tmp/onionpress/build/onionpress-rw.dmg`, so every published
DMG carries a developer's home directory path. Regenerating on another
machine would substitute that machine's path rather than remove it — the file
is inherently machine-specific, which is exactly why it is a committed capture
and not a build step.

### Recapturing it

Only needed if the window layout changes. It requires Finder automation
permission, which is why `build-dmg-simple.sh` does not do this
automatically:

1. Run `build/build-dmg-simple.sh` with `build/dmg-assets/DS_Store` moved
   aside, so the AppleScript styling path runs.
2. While the read-write image is still mounted, check the window looks right.
3. Copy `/Volumes/OnionPress/.DS_Store` back here **as `DS_Store`**.

**The missing leading dot is deliberate.** The repo's `.gitignore` has a
`.DS_Store` rule; naming this file `.DS_Store` makes git ignore it silently,
and the next DMG build loses all of its window styling with no error.
